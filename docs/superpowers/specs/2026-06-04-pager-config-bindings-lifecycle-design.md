# Pager 配置/产物/构建一致化设计

> 日期：2026-06-04
> 范围：bindings 生成式策略 + 配置/DB 路径分离 (dev vs prod) + Makefile 集成 + 小幅 polish
> 工作量：~2h

---

## 1. 背景

上一轮 4-bug 修复（`2026-06-03-pager-event-parsing-bugfix-design.md`）落地后，留下三类一致性问题需要本 spec 收尾：

1. **Wails bindings 漂移**：`frontend/bindings/` 是 codegen 产物，但仓库当前是混合态 — 16 个文件已追踪，最新生成的 `wails/v3/pkg/services/notifications/*` 三个文件未追踪。这是因为开发者没每次 `make bindings` + `git add`，binding 与 Go 端 API 慢慢对不上。
2. **dev 与 prod 共用配置目录**：当前 `config.DefaultPath()` 一律返回 `~/.config/pager/settings.json`，开发时改坏配置会污染日常使用的 Pager.app；DB 同理。SQLite 还出现过 cwd-relative 泄漏到 `internal/infra/store/pager.db`。
3. **不符合 macOS 原生约定**：`~/.config/pager/` 是 XDG/Linux 风格；macOS 应用应该用 `~/Library/Application Support/Pager/`。CLAUDE.md 写明"macOS only"但路径用了非原生风格。

本 spec 一次性解决三件事，并捎带两个 final-review 留下的非阻塞 polish。

### 1.1 现有数据迁移状态

老数据（66 sessions / 9782 events / 1 settings.json + 3 SQLite 文件）已**手工**从 `~/.config/pager/` mv 到 `<repo>/.config/pager/`。本 spec 仅负责代码层面让程序认得新路径；**不再涉及数据搬运动作**。

## 3. 详细设计

### § 3.1 Bindings 生成式策略 (方案 A)

**当前状态**：
- 已追踪：`frontend/bindings/{encoding,time,pager/internal/...,wails/v3/internal/}` 共 16 个 .js / .d.ts 文件
- 未追踪：`frontend/bindings/wails/v3/pkg/services/notifications/{index.js,models.js,notificationservice.js}` 共 3 个文件
- 这些都是 `wails3 generate bindings` 的输出

**目标状态**：完全停止追踪。以 Makefile 为唯一生成入口，每次 `make dev` / `make run` / `make build` 自动 codegen。

**变更动作**：

1. **一次性 untrack**：
   ```bash
   git rm -rf --cached frontend/bindings/
   ```
   约 19 个文件的 deletion 记录会进入 commit，但本地工作树文件保留（用户工作流不受影响）。

2. **`.gitignore` 增加**：
   ```
   # Wails bindings — codegen artifact, regenerated by `make bindings`
   frontend/bindings/
   ```

3. **`Makefile` 新增 target**：
   ```makefile
   ## Generate Wails bindings from Go services
   bindings:
   	wails3 generate bindings
   ```

4. **wire 进现有目标的前置依赖**（沿用 § install-bridge 的模式）：
   - `dev: stop install-bridge bindings`（替换现有 `dev: stop install-bridge`）
   - `run: build-go install-bridge bindings`（替换现有 `run: build-go install-bridge`）
   - `build: frontend-build install-bridge bindings`（替换现有 `build: frontend-build install-bridge`）

5. **`.PHONY` 添加 `bindings`**。

6. **`help` target 加入新行**：
   ```makefile
   @echo "  make bindings       Regenerate Wails bindings (Go → TS)"
   ```
   插在 `make bridge` 行之后、`make install-bridge` 行之前（按字母 + 语义分组）。

**Failure-mode**：`wails3 generate bindings` 失败 → make stops with non-zero exit → dev/run/build 无法继续。这是预期：binding 与 Go 端不一致时不应允许 build 进入下一步。

### § 3.2 Config / Store 路径策略

**`internal/infra/config/config.go`** 新增共享函数 `BaseDir()`，重构 `DefaultPath()` 基于它：

```go
// BaseDir returns the directory under which all Pager runtime data
// (settings.json, pager.db, WAL files, etc.) lives. Resolution order:
//
//  1. PAGER_CONFIG_DIR env var (highest priority — used by `make dev` and tests)
//  2. ~/Library/Application Support/Pager/ (macOS-native default for production)
//
// The directory is NOT created here; callers should MkdirAll on first write.
func BaseDir() string {
    if envDir := os.Getenv("PAGER_CONFIG_DIR"); envDir != "" {
        return envDir
    }
    home, _ := os.UserHomeDir()
    return filepath.Join(home, "Library", "Application Support", "Pager")
}

// DefaultPath returns the absolute path to settings.json under BaseDir().
func DefaultPath() string {
    return filepath.Join(BaseDir(), "settings.json")
}
```

**`internal/infra/store/sqlite.go`**：DB 路径改为基于 `config.BaseDir()`：

```go
// Existing OpenDefault (or wherever the path was hardcoded) becomes:
func OpenDefault() (*sqliteStore, error) {
    dbPath := filepath.Join(config.BaseDir(), "pager.db")
    return Open(dbPath)
}
```

**优先级表**：

| 场景 | 触发方式 | BaseDir() 返回 |
|---|---|---|
| `make dev` / `make run` | Makefile 注入 `PAGER_CONFIG_DIR` | `<repo>/.config/pager/` |
| `make build` 后双击 .app | 无 env var | `~/Library/Application Support/Pager/` |
| 直接跑 `./bin/Pager`（非 Makefile） | 无 env var | `~/Library/Application Support/Pager/` |
| 测试用临时目录 | `PAGER_CONFIG_DIR=$(mktemp -d)` | tmpdir |

**单测**：`internal/infra/config/config_test.go` 新增 `TestBaseDir_Override` + `TestBaseDir_Default`：
- override：设 env → 期望返回 env
- default：不设 env → 期望路径以 `Library/Application Support/Pager` 结尾

### § 3.3 Makefile

合并 § 3.1 的 bindings 改动与 § 3.2 的 env var 注入。完整改动清单：

```diff
- .PHONY: dev build run clean test bridge install-bridge install-hooks ... 
+ .PHONY: dev build run clean test bridge install-bridge bindings install-hooks ...

+ ## Generate Wails bindings from Go services
+ bindings:
+ 	wails3 generate bindings

- dev: stop install-bridge
- 	wails3 dev -config ./build/config.yml -port $(VITE_PORT)
+ dev: stop install-bridge bindings
+ 	PAGER_CONFIG_DIR="$(PWD)/.config/pager" \
+ 		wails3 dev -config ./build/config.yml -port $(VITE_PORT)

- build: frontend-build install-bridge
+ build: frontend-build install-bridge bindings
  	wails3 package

- run: build-go install-bridge
- 	./$(APP_BIN)
+ run: build-go install-bridge bindings
+ 	PAGER_CONFIG_DIR="$(PWD)/.config/pager" ./$(APP_BIN)
```

`build` target **不**注入 env var — `wails3 package` 产出的 `.app` 是给最终用户的，运行时不应预设 env var。

**`help` 输出增加**：
```makefile
@echo "  make bindings       Regenerate Wails bindings (Go → TS)"
```
插在第 14 行附近、`make bridge` 之后。

### § 3.5 CLAUDE.md

并列于现有 "Bridge Binary Lifecycle" 章节，新增两节。位置：`Bridge Binary Lifecycle` 之后、`Code Conventions` 之前。

```markdown
## Wails Bindings Lifecycle

`frontend/bindings/` is build-output, generated by `wails3 generate bindings`
from Go services in `internal/wails/*_svc.go` and entities in
`internal/domain/entity/`. NOT tracked in git.

`make dev` / `make run` / `make build` regenerate bindings as a prerequisite
(via the Makefile `bindings` target). If you change a `XxxBinding` method
signature or an entity that bindings reference, the next `make dev` picks it
up automatically.

If you ever see "binding X not found" in the frontend console, run
`make bindings` manually — fresh checkouts also need it before first dev.

## Configuration Paths

Pager runtime data (`settings.json`, `pager.db`, WAL files) lives under
a single base directory chosen at startup:

| Mode                  | Trigger                              | BaseDir()                                  |
|-----------------------|--------------------------------------|--------------------------------------------|
| Development           | `make dev` / `make run`              | `<repo>/.config/pager/`                    |
| Production (.app)     | Double-click Pager.app               | `~/Library/Application Support/Pager/`     |
| Test / ad-hoc         | `PAGER_CONFIG_DIR=/tmp/X` set        | `/tmp/X/`                                  |

Resolution order in `config.BaseDir()`:
1. `PAGER_CONFIG_DIR` env var (highest priority)
2. `~/Library/Application Support/Pager/` (macOS-native default)

`make dev` / `make run` set `PAGER_CONFIG_DIR=$(PWD)/.config/pager` so dev
work never pollutes your installed Pager.app's data. The dev directory
`<repo>/.config/` is gitignored.

`make build` does NOT set the env var — the resulting `.app` ships to end
users who get the macOS-native default.
```

### § 3.6 Polish carry-overs

#### § 3.6.1 DSL `//` 负向测试

`internal/adapter/bridge/rules_test.go` 新增 1 个测试，钉死当前 `//` reserved-token 语义。当前 DSL 在 token body 里把 `//` 视为 fallback 分隔符；如果 yaml 规则里写了 `{$.url|default:http://x}`，会被错误 split。这个测试明示该限制（实际 DSL 行为：split 后第一段 `$.url|default:http:` 在 path 缺失时由 default filter 返回 `"http:"`，被 fallback chain 当作"非空首项"接受）：

```go
// TestEvaluate_FallbackOperator_DocumentsHTTPURLLimitation pins the documented
// constraint that "//" inside a token body is reserved for the fallback
// operator. Future authors trying to use raw URL literals like "http://x" in
// a default: filter argument will trip this — by design.
//
// Trace for input "{$.url|default:http://x}" against payload "{}":
//   1. Token body "$.url|default:http://x" contains "//" → fallback chain
//   2. Split on "//": ["$.url|default:http:", "/x"]
//   3. Recurse on first part "$.url|default:http:":
//      - $.url path missing (exists=false)
//      - filter default:http: triggers, returns "http:"
//   4. First non-empty wins → "http:"
//
// The user wanted "http://x". They got "http:". The // got eaten as a
// fallback delimiter. This test exists so any future change to the parse
// order of // vs | gets caught and forces a deliberate decision.
func TestEvaluate_FallbackOperator_DocumentsHTTPURLLimitation(t *testing.T) {
    got := Evaluate("{$.url|default:http://x}", []byte(`{}`), "X")
    if got != "http:" {
        t.Errorf("got %q, want %q — // constraint may have changed; update doc + DSL", got, "http:")
    }
}
```

#### § 3.6.2 删除 `[认证]` 防御性 label

`internal/adapter/bridge/extractor.go::notificationTypeLabel` 当前有：

```go
case "auth_success":
    return "[认证] " // Bug 1 already drops these at bridge entry; defensive.
```

但 `cmd/bridge/main.go::shouldDrop` 已经在 bridge 入口拦截 `Notification + 空 session_id`，CodeBuddy 的 `auth_success` 都属于这种。该分支在生产中不可达。

**变更**：删除该 case。同时删除 `extractor_test.go` 中的 `TestExtractEventContent_Notification_AuthSuccess`（断言不可达分支没有意义）。

`UnknownType` 测试（NotificationType=""）覆盖了 default 分支，足够。

## 8. 风险与回滚

| 风险 | 缓解 |
|---|---|
| `make build` 产出的 .app 在没有 env var 时无法找数据 | 依赖 macOS 原生路径在第一次启动时由 `os.MkdirAll(0o755)` 自动创建；schema.sql 自动建表；settings 缺失时回退 `Defaults()` — 都是已有机制 |
| `wails3 generate bindings` 在 fresh checkout 没装 wails3 CLI | 项目本来就要求装 wails3（CLAUDE.md 已写），文档化在 README/CLAUDE.md |
| dev 数据 (`<repo>/.config/pager/`) 累积变大被 ignored，开发者不知情 | `.config/` 在 .gitignore，但本地占空间；周期性 `du -sh .config/` + 手动 `vacuum` SQLite |
| 已迁移的 SQLite WAL 在 first open 时是否能 checkpoint | 已 integrity check（PRAGMA integrity_check → ok），WAL 在下次正常 open 时由 SQLite 自动 checkpoint |
| 用户既想 dev 又想偶尔点 .app 看 prod 行为 | 设计如此 — 两者完全隔离。dev 写 `<repo>/.config/`，prod 写 `~/Library/Application Support/Pager/`，互不干扰 |

回滚策略：单 commit 可 git revert（涉及 Makefile + .gitignore + 4 个 Go 文件 + CLAUDE.md），无 schema migration、无外部依赖变化。
